# 10. Seed.AI — キャラAI＋メタAI

[← 前: 09_Motion](09_Motion.md) | [索引](README.md) | [次: 11_StageGen →](11_StageGen.md)

## この章で分かること

- 採点式（ユーティリティ型）AIで「今いちばんやりたい行動」を選ぶ仕組みと、その決定性
- キャラAIとメタAI（ディレクター）の役割分担——ユニットを直接動かさず指示書だけで采配する理由
- メタAIの手心（HP が減るほど敵の攻撃間隔が延びる・攻撃性が下がる）の実際の式と数値
- `IAiConsideration` を自作して思考候補を増やす手順（クールダウンを黒板で持つ実戦例つき）
- `[O]` 自動操縦が「制御経路はプレイヤーと共通」であることの意味と、それが何を可能にするか

## 前提

先に [08_Character](08_Character.md) を読んでください。この章は次の知識を使います。

- **`ICharacterLogic` / `Think(in LogicFrame)`**: 「次に何をしたいか」を決める頭脳の差し込み口。`AiBrain` はこの実装のひとつ
- **`CharacterIntent`**: 意図の 3 層構造（移動方向・ガード継続・離散行動の要求1件＋荷物）。AI も人間の入力もこの語彙で話す
- **`ManualLogic`**: 手動入力の一時保管場所（`SetMove` / `SetGuard` / `RequestAction`）。自動操縦の注入先
- **`UnitController`**: 毎 Tick で `LogicFrame` を組み、頭脳に考えさせ、意図を Agent へ流す
- **`CharacterRegistry`**: 在籍名簿。契約の `ICharacterQuery`（生存・位置）と `ICharacterRoster`（陣営列挙）を兼ねる
- **`TickPipeline`**（[03_Clock](03_Clock.md)）: 1 フレームの実行順を登録順で保証する仕組み

この章が初出の主な用語: ユーティリティAI、Consideration、メタAI（ディレクター）、指示書、黒板（ブラックボード）、攻撃権トークン、攻撃性‰、動的難易度調整、入力エミュレート。

## 1. これは何か

Seed.AI は「敵の頭の中」と「戦場の采配」を分けて実装するための純C#基盤です。`Assets/Script/AI/Runtime/` 配下にあり、asmdef は `Seed.AI`（参照は `Seed.Hub` / `Seed.Hub.Contracts` / `Seed.Character`）。**MonoBehaviour は 1 つもありません**。

08 章のデモは `ManualLogic` に人間のキー入力を書いて動いていました。ここに敵を足すとき、素朴に「敵用の `ICharacterLogic` に `if` を並べる」と 3 つの問題が起きます。

1. **条件の爆発**。「射程内なら攻撃、ただし味方が既に攻撃中なら待つ、ただし体力が低ければ下がる…」を `if` の入れ子で書くと、行動を 1 つ足すたびに既存の分岐を全部読み直す必要が出ます。本基盤は候補ごとに独立したクラス（`IAiConsideration`）を作り、**得点で競わせる**方式にしました。行動追加は「1 クラス＋登録 1 行」で、既存候補には触りません。
2. **難易度調整の置き場がない**。「プレイヤーが弱っていたら攻撃を緩める」を各ユニットの思考の中に書くと、敵が 10 体いれば 10 箇所に散ります。本基盤はメタAI（`AiDirector`）を分け、全体の采配を 1 箇所に集約します。
3. **プレイヤーと NPC で制御経路が二重化する**。AI 用に別の移動処理・別の攻撃処理を書くと、片方だけバグる・片方だけ HUD が更新されない、が起きます。本基盤の AI は人間と同じ `CharacterIntent` しか返さず、`InputEmulator` を使えば人間の置き場（`ManualLogic`）へ書き込むことすらできます。

> 📖 **用語 — ユーティリティAI（採点式AI）**: 候補となる行動それぞれに「今それをやりたい度」を数値で計算させ、最高得点の候補を実行する方式。「攻撃 100 点 / 追跡 50 点」のように点数の大小だけで優先順位が決まるため、候補を足しても既存の候補の実装を変えずに済みます。効用（utility）を比べるのでこの名前です。

> 📖 **用語 — ビヘイビアツリー / 有限状態機械（対比）**: どちらも AI の定番構造で、前者は木構造のノードを上から順に試し、後者は状態と遷移条件を並べます。いずれも「候補どうしの繋がり（親子・遷移矢印）」を人が設計する必要があり、候補追加のたびに構造の編集が発生します。Seed が採点式を選んだのは、候補が**互いを知らずに並列に増やせる**ことを優先したためです（行動の真実そのものは 08 章の Behavior 状態機械が持っており、AI 側で状態を二重に持たない設計です）。

> 📖 **用語 — メタAI（ディレクターAI）**: 個々のキャラクターの賢さとは別に、戦場・ゲーム全体を見て「体験としてどうあるべきか」を采配する上位のAI。攻撃の順番待ち、難易度の手心、注目対象の割り当てなどを担います。本基盤では `AiDirector` 派生がそれで、**ユニットを直接動かさず**、指示書（`AiOrders`）を書き換えるだけで介入します。

## 2. 全体像

### 部品表

| 部品 | 役割 |
|---|---|
| `AiBrain` | `ICharacterLogic` 実装。毎 Think で全候補を採点し、最高得点の `Act` の意図を返す |
| `IAiConsideration` | 思考候補 1 つ。`float Score(in AiContext)`（0 以下＝不参加）と `CharacterIntent Act(in AiContext)` |
| `AiContext` | 思考 1 回ぶんの視界（`readonly struct`）。Frame / Query / Roster / Blackboard / Orders |
| `AiBlackboard` | ユニット 1 体ぶんの記憶。`Dictionary<int, float>` と `Dictionary<int, int>` ＋AI時計 `TimeSeconds` |
| `AiOrders` | 指示書（`readonly struct`）。`AttackPermitted` / `AggressionPermille` / `FocusTarget` |
| `IOrderSource` / `NullOrderSource` | 指示書の取得窓口と、常に全許可を返す既定実装 |
| `AiDirector` | メタAIの抽象基底（`IOrderSource` 実装）。`SetOrders` / `ClearOrders` ＋ `abstract void Tick(float)` |
| `AttackTokenPool` | 同時攻撃数の上限管理（`TryAcquire` / `Release` / `Clear` / `ActiveCount` / `IsHolder`） |
| `InputEmulator` | AI の意図を `ManualLogic` へ注入する橋（`Drive` / `ReleaseAll`） |

具体的な思考候補と采配ルールは**方針なのでアプリ側**にあります（`Sample_ChaseConsideration` / `Sample_AttackConsideration` / `Sample_AiTargeting` / `Sample_BattleDirector`）。基盤は器だけを提供します。

### データの流れ

```
[合成ルート] Sample_BattlePhase.OnEnter
   Sample_BattleDirector を new → AiBrain(registry, registry, director) の第3引数へ注入

1フレーム（TickPipeline・登録順で実行）
 Input      : HandlePlayerInput ─ 自動操縦ONなら InputEmulator.Drive(playerBrain.Think(...))
 Simulation : ① director.Tick(dt) ── SetOrders(敵ID, AiOrders(攻撃権, 攻撃性‰, 注目対象))
              ② characters.Tick(dt)
                   └ UnitController.Tick ─ LogicFrame（自分の位置・向き・生死・dt）を組む
                        └ AiBrain.Think(in frame)
                             ├ Blackboard.TimeSeconds += frame.DeltaTime   ← AI時計
                             ├ AiContext ← Frame / Query / Roster / Blackboard
                             │              ＋ orders.GetOrders(frame.SelfId)
                             ├ 登録順に Score を採点（score > bestScore で王座交代）
                             └ 勝者の Act(in context) → CharacterIntent
                                  └ Agent.SetIntent → Behavior 状態機械（08章）が解釈
                                       └ BehaviorStarted(Attack) → director.NotifyAttackStarted（攻撃権の消費）
 Drain     : CharacterDamaged 購読 → director.NotifyPlayerHp（手心の入力が戻る）
```

> 📖 **用語 — 合成ルート**: アプリ起動時に各基盤を `new` して配線する唯一の場所。この章では `Sample_BattlePhase.OnEnter`（戦闘フェーズの組み立て）が該当し、`AiBrain` の生成・候補の登録・ディレクターの注入・Tick 順の宣言をすべてここで行います。

## 3. 動かして試す

1. Unity で任意のシーンを開き、Hierarchy で右クリック → Create Empty で空の GameObject を作成
2. Inspector の Add Component から `Sample_GameFlowRunner` を追加（カメラ・ライトは無ければ自動生成されます）
3. Play を押す。左上にホーム画面のテキストメニューが出る
4. **`[1]` キー**で「出撃: 草原」→ 戦闘フェーズへ。Hierarchy に `Stage_Grassland` が現れ、その下に青カプセル（Player）と灰キューブ（Enemy）が生成される
5. 何もせず観察する。敵が**自分から近づいてきて**、2.2m 手前で止まります（`Sample_ChaseConsideration` の停止距離）。そこから射程 2.8m 内かつディレクターの攻撃権が下りた瞬間だけ攻撃を振ります
6. **わざと殴られる**。草原の基準間隔は 4 秒です。HP 満タンなら 4 秒ごとに攻撃が来ますが、HP が半分になると 6 秒、1/4 になると 7 秒に延びます（式は 5 節）。被弾するほど敵の攻撃が緩くなるのが体感できます
7. **`[O]` キー**で自動操縦 ON。プレイヤーの青カプセルが**勝手に敵へ近づき**（停止距離 1.8m）、射程 2.4m 内で攻撃を振り始めます。HUD の HP も普通に減り、ヒットストップ（0.06 秒）も普通に掛かります
8. 自動操縦中に `[W][A][S][D]`・`[1]`・`[G]` を押しても**効きません**（`HandlePlayerInput` が早期 return する）。一方 `[T]`（3D⇔2D 切替）・`[P]`（ポーズ）・`[B]`（ホームへ）は効きます——見た目・時間・フェーズは操縦者と無関係な関心事だからです
9. もう一度 **`[O]`** で解除。`InputEmulator.ReleaseAll()` が呼ばれ、その場で移動が止まり `[W][A][S][D]` が復帰します
10. `[2]`（火山）で出撃し直すと基準間隔が 2.5 秒になり、敵の攻撃が明らかに速くなります（ステージ仕様 `Sample_StageSpec.EnemyAttackInterval` の値差）

Console にこの基盤専用のログは出ません（採点も指示書もログを出しません）。動作の検証は EditMode テスト `AiFoundationTests`（7 件）が担います。Window > General > Test Runner の EditMode タブから `Seed.AI.Tests` を実行してください。

## 4. コードで使う

### 最小例 — 敵 1 体に頭脳を載せる（メタAI無し）

```csharp
using Seed.AI;
using Seed.Character;
using Seed.Hub.Contracts;

// CharacterRegistry は ICharacterQuery と ICharacterRoster を兼ねるので同じ参照を2回渡す
var registry = _characters.Registry;

// 第3引数（IOrderSource）を省略 = NullOrderSource = 常に全許可（攻撃権あり・攻撃性1000‰）
var brain = new AiBrain(registry, registry)
    .With(new Sample_ChaseConsideration(FactionId.Players, stopDistance: 2.2f))   // 得点 最大50
    .With(new Sample_AttackConsideration(FactionId.Players, moveId, range: 2.8f)); // 得点 100

// Controller が毎 Tick で LogicFrame を組み、brain.Think を呼ぶ（結線はこれだけ）
_enemies.Add(new EnemyController(agent, brain));
```

`With` は自分を返すので数珠つなぎに書けます。**登録順が同点時の優先度を兼ねる**ので、順序には意味があります。

### 実戦例 — 思考候補を自作する（クールダウン＋間合い取り）

思考候補は「Score で立候補し、Act で意図を返す」だけの小さなクラスです。以下は `Assets/Script/App/Samples/` へ足す想定の 2 つの候補です。

```csharp
using Seed.AI;
using Seed.App;          // Sample_AiTargeting を使う
using Seed.Character;
using Seed.Hub.Contracts;
using UnityEngine;

/// <summary>黒板のキー（ScreenId と同じ流儀でアプリ側が発番する）。</summary>
public static class MyAiKeys
{
    public const int LastSpecialTime = 100; // 最後に必殺技を撃った「AI時刻」
}

/// <summary>必殺技: 攻撃より強い得点だが、クールダウン中は立候補しない。</summary>
public sealed class SpecialMoveConsideration : IAiConsideration
{
    private readonly FactionId _targetFaction;
    private readonly int _moveId;
    private readonly float _range;
    private readonly float _cooldown;
    private readonly CharacterId[] _buffer = new CharacterId[8]; // 列挙用。毎回 new しない

    public SpecialMoveConsideration(FactionId targetFaction, int moveId, float range, float cooldown)
    {
        _targetFaction = targetFaction; _moveId = moveId; _range = range; _cooldown = cooldown;
    }

    public float Score(in AiContext context)
    {
        if (!context.Orders.AttackPermitted) { return 0f; }        // 指示書に従う（メタAIの采配）
        // 既定値を大きな負にしておくと「初回は即撃てる」になる
        var last = context.Blackboard.GetFloat(MyAiKeys.LastSpecialTime, -999f);
        if (context.Blackboard.TimeSeconds - last < _cooldown) { return 0f; } // クールダウン中
        if (!Sample_AiTargeting.TryFindTarget(in context, _targetFaction, _buffer, out _, out var p))
        {
            return 0f;                                            // 相手が居ない
        }
        return Vector3.Distance(context.Frame.SelfPosition, p) <= _range ? 120f : 0f; // 通常攻撃100 に勝つ
    }

    public CharacterIntent Act(in AiContext context)
    {
        // 記憶への書き込みは Act で行う（Score は読み取りのみ、が本基盤の規約）
        context.Blackboard.SetFloat(MyAiKeys.LastSpecialTime, context.Blackboard.TimeSeconds);
        return new CharacterIntent(Vector3.zero, false, BehaviorKey.Attack, _moveId);
    }
}

/// <summary>間合い取り: 攻撃権が無いあいだは下がる（固定30点で追跡と競う）。</summary>
public sealed class KeepDistanceConsideration : IAiConsideration
{
    private readonly FactionId _targetFaction;
    private readonly CharacterId[] _buffer = new CharacterId[8];

    public KeepDistanceConsideration(FactionId targetFaction) { _targetFaction = targetFaction; }

    public float Score(in AiContext context)
    {
        if (context.Orders.AttackPermitted) { return 0f; }         // 攻めていいなら下がらない
        return Sample_AiTargeting.TryFindTarget(in context, _targetFaction, _buffer, out _, out _)
            ? 30f : 0f;
    }

    public CharacterIntent Act(in AiContext context)
    {
        Sample_AiTargeting.TryFindTarget(in context, _targetFaction, _buffer, out _, out var p);
        var away = context.Frame.SelfPosition - p;                 // 相手と逆向き
        away.y = 0f;
        return new CharacterIntent(away.normalized, false, BehaviorKey.None, 0);
    }
}
```

登録は既存の構築箇所（`Sample_BattlePhase.BuildEnemyUnit`）へ 1 行ずつ足すだけです。**強い候補を先に**書くと同点時に勝ちます。

```csharp
var brain = new AiBrain(registry, registry, _director)
    .With(new SpecialMoveConsideration(FactionId.Players, specialId, range: 3f, cooldown: 8f))
    .With(new Sample_AttackConsideration(FactionId.Players, moveId, range: 2.8f))
    .With(new Sample_ChaseConsideration(FactionId.Players, stopDistance: 2.2f))
    .With(new KeepDistanceConsideration(FactionId.Players));
```

### 実戦例 — メタAI（同時攻撃数の制限＋注目対象の指定）

```csharp
using Seed.AI;
using Seed.Hub.Contracts;

/// <summary>敵が何体居ても同時に殴りかかるのは2体まで、というメタAIの定番采配。</summary>
public sealed class SquadDirector : AiDirector
{
    private readonly CharacterId[] _members;
    private readonly CharacterId _playerId;
    private readonly AttackTokenPool _tokens = new AttackTokenPool(maxConcurrent: 2);

    public SquadDirector(CharacterId[] members, CharacterId playerId)
    {
        _members = members; _playerId = playerId;
    }

    /// <summary>攻撃が終わった・死んだユニットのトークンを返すのはディレクターの責務。</summary>
    public void NotifyAttackFinished(CharacterId id) { _tokens.Release(id); }

    public override void Tick(float deltaTime)
    {
        for (var i = 0; i < _members.Length; i++)
        {
            // TryAcquire は早い者勝ちで決定的（乱数を使わない）。保持済みなら true のまま
            var permitted = _tokens.TryAcquire(_members[i]);
            SetOrders(_members[i], new AiOrders(
                attackPermitted: permitted,
                aggressionPermille: permitted ? 1000 : 500, // 待機側は追い方も緩める
                focusTarget: _playerId));                   // 狙いを固定（ヘイト計算の置き場もここ）
        }
    }
}
```

合成ルート側では **ユニットの Tick より前**にディレクターを回します。

```csharp
_pipeline.Add(TickPhase.Simulation, dt => _director.Tick(dt));      // ① 采配
_pipeline.Add(TickPhase.Simulation, dt => _characters.Tick(dt));    // ② 思考（①の指示書を読む）
```

> 📖 **用語 — 攻撃権トークン / セマフォ**: 「同時に使える権利の枚数」を数で管理する古典的な手法。`AttackTokenPool` は枚数上限（`maxConcurrent`、1 未満は 1 に丸められる）まで `HashSet<CharacterId>` へ保持者を記録し、満員なら `TryAcquire` が false を返します。囲まれた瞬間に全員から殴られる「理不尽」を、AI を賢くするのではなく**枚数の制約**で解決します。

> 📖 **用語 — 黒板（ブラックボード）**: AI が思考の継続に必要な値を置く共有メモ帳。`AiBlackboard` は `int` キーで `float` / `int` / `CharacterId` を読み書きし（未設定キーは既定値が返る）、`TimeSeconds` は `AiBrain` が毎 Think で `frame.DeltaTime` を足すAI時計です。クールダウンを「毎フレーム減算するカウンタ」ではなく「発動時刻を覚えて経過を比べる」形で書けるので、値がフレーム落ちで散りません。

## 5. 仕組み

### 採点の 1 回ぶん

`AiBrain.Think(in LogicFrame frame)` がすることは 4 つだけです。

1. `Blackboard.TimeSeconds += frame.DeltaTime` ——AI時計を進める
2. `AiContext` を組む。Orders は `_orders.GetOrders(frame.SelfId)` で**その瞬間の指示書**を引く
3. `_considerations` を登録順に走査し、`score > bestScore`（初期値 `0f`）なら王座交代。つまり **0 以下は不参加**で、**同点は先着が勝つ**
4. 勝者が居れば `best.Act(in context)`、居なければ `CharacterIntent.None` を返す

`Act` は勝者にしか呼ばれません。テスト `Brain_PicksHighestScore_FirstWinsTies` は 50 点で同点の 2 候補のうち先着だけ `ActCount` が 1 になることを検証しています。

> 📖 **用語 — 決定性**: 同じ入力から必ず同じ結果が出る性質。`AiBrain` は走査順が固定・同点解決が先着固定・`AttackTokenPool` の取得が早い者勝ちで、どこにも乱数が入りません。だから 12 章の記録/リプレイと矛盾しません。**乱数を使いたい候補には、ゲーム側の決定的乱数を注入してください**（`UnityEngine.Random` を直接読むとリプレイが壊れます）。

> 📖 **用語 — `in` 引数と `readonly struct`**: C# で構造体を「コピーせず・書き換えもさせず」渡す書き方。`Score(in AiContext)` は毎フレーム・候補の数だけ呼ばれるため、`AiContext` / `AiOrders` / `LogicFrame` / `CharacterIntent` はすべて `readonly struct` で、参照渡し（`in`）しています。ヒープ確保が発生しないので GC が動きません。

### メタAIの手心（実際の式）

`Sample_BattleDirector` は 3 つの入力（時間・プレイヤー HP・攻撃開始通知）から指示書を作ります。

```csharp
public float CurrentInterval => _baseInterval * (2f - _playerHpRatio);           // 攻撃間隔
// Tick 内
_timer += deltaTime;
var aggression = 400 + (int)(600 * _playerHpRatio);                             // 攻撃性‰
SetOrders(_enemyId, new AiOrders(
    attackPermitted: _timer >= CurrentInterval,
    aggressionPermille: aggression,
    focusTarget: _playerId));
```

草原（基準 4 秒・`Sample_StageSpec.EnemyAttackInterval`）での実数値です。

| プレイヤー HP 率 | 攻撃間隔 `CurrentInterval` | 攻撃性 `AggressionPermille` | 追跡の得点 `50×‰/1000` |
|---|---|---|---|
| 1.0（満タン） | 4.0 秒 | 1000‰ | 50.0 |
| 0.5 | 6.0 秒 | 700‰ | 35.0 |
| 0.25 | 7.0 秒 | 550‰ | 27.5 |
| 0.0 | 8.0 秒 | 400‰ | 20.0 |

HP 率は `NotifyPlayerHp(remainingHp, maxHp)` で更新され、その呼び出し元は `CharacterDamaged` の購読（対象がプレイヤーのときだけ）です。攻撃側のループはこう閉じます——攻撃権が下りる → 射程内で `Sample_AttackConsideration` が 100 点で勝つ → Behavior が Attack に遷移 → `BehaviorStarted` が `NotifyAttackStarted` を呼び **`_timer` が 0 に戻る** → 次の間隔まで `AttackPermitted` は false。

なお `CurrentInterval` は「最短間隔」です。権利が下りても敵が射程外なら攻撃は発生せず、`_timer` は伸び続けて距離が詰まった瞬間に振られます。

> 📖 **用語 — 動的難易度調整（DDA）**: プレイヤーの状況に応じて難易度を実行時に変える設計。ここでは「弱っている相手には攻撃を遅くする」形で、負け寸前の緊張感を保ちながら理不尽な即死を避けます。手心のロジックが**ディレクター 1 クラスに閉じている**ので、難易度設定の追加も差し替えもここだけで済みます。

> 📖 **用語 — ‰（パーミル）**: 千分率。`AggressionPermille` は 1000 が全開で、`50f * ‰ / 1000f` のように得点へ掛けて使います。整数で持つと保存・比較・データ入力での丸め誤差がなく、`float` の 0〜1 より扱いが安定します（本プロジェクト共通の流儀で、モーションの正規化‰イベントと同じ考え方です）。

**注意**: 攻撃性の低下が実際に行動を変えるのは、**同じ場面で競う別候補が居るとき**です。デモの敵は「追跡」と「攻撃」の 2 候補だけなので、追跡の得点が 50 → 20 に落ちても射程外では追跡が唯一の立候補者であり、選ばれる行動は変わりません（移動方向は正規化されるため速度も落ちません）。4 節の `KeepDistanceConsideration`（固定 30 点）を足すと初めて逆転が起き、`‰ < 600`（HP 率 1/3 未満）で「追う」より「下がる」が勝ちます。**攻撃性は速度の係数ではなく、候補どうしの綱引きの重み**です。

### 自動操縦は「制御経路がプレイヤーと共通」であること

`[O]` で起きていることは、`HandlePlayerInput` の中で入力の**書き手が入れ替わるだけ**です。

```csharp
if (_isAutopilot)
{
    var agent = _playerController.Agent;
    var pose = agent.ActiveActor.Pose;
    var frame = new LogicFrame(_playerId, pose.Position, pose.Rotation, agent.IsAlive, deltaTime);
    _playerEmulator.Drive(_playerBrain.Think(in frame));  // AIの意図を「入力として」書き込む
    return;                                              // 物理キーは読まない
}
```

`InputEmulator.Drive` の中身は 3 行で、`ManualLogic.SetMove` / `SetGuard` /（要求があれば）`RequestAction` を呼ぶだけです。つまり **`ManualLogic` から下流（`PlayerController` → `CharacterAgent` → `CharacterActor` → Behavior → Avatar → HUD）は 1 行も変わりません**。これが実務で効いてくる点は 4 つあります。

- **バグが二重化しない**: AI 専用の移動経路が無いので、「手動では壁に止まるが AI はすり抜ける」が構造的に起きません。当たり判定（`IMotionSolver`）もガード仕様も共通です
- **HUD・イベント・セーブが自動で正しい**: HP 表示もヒットストップも `AttackRequested` の発行も、書き手が誰かを知りません
- **転用が効く**: デモプレイ（放置デモ）・チュートリアルの誘導・カットシーンの半自動操作・オートバトル・AI 対戦のリプレイ検証が、すべてこの 1 クラスで実現できます
- **検証できる**: テスト `InputEmulator_ReproducesIntentThroughManualLogic` は、意図が `ManualLogic` を経由しても移動・ガード・行動キー・荷物（技ID 42）まで等価に再現されることを確認しています。これが「経路が共通」の機械的な証明です

デモのプレイヤー用頭脳（`_playerBrain`）には**ディレクターを渡していません**。したがって `NullOrderSource` が使われ、攻撃権は常に true・攻撃性は 1000‰ です——自動操縦のプレイヤーには手心が掛かりません。

### 三大規約との関係

- **状態は Tick、艶は Update**: 採点も采配も Tick 側（`TickPipeline` の `Simulation`）でだけ動きます。`AiBrain` は `Transform` にも `Time.deltaTime` にも触らず、時間は `frame.DeltaTime` と `Blackboard.TimeSeconds` から受け取ります。だから ポーズ・ヒットストップ・スローモーションが AI にもそのまま効き、EditMode テストでも `dt` を手で与えて検証できます
- **方針は App**: 「どのくらい近づいたら攻撃するか」「弱った相手をどれだけ見逃すか」はゲームの個性＝方針です。基盤側に具体的な `IAiConsideration` 実装は 1 つも無く、`AiDirector` は `Tick` が `abstract` の空箱です
- **命令の処理者は1基盤**: AI は Hub へ命令を publish しません。返すのは `CharacterIntent` だけで、それを解釈して行動へ変えるのは 08 章のキャラクター基盤ただ一つです。逆に AI が世界へ触れる窓は `ICharacterQuery` / `ICharacterRoster`（読み取り専用）に限られます。「なぜ敵がここで攻撃したのか」の答えが常に「その瞬間の得点表と指示書」に一本化されます

## 6. よくあるつまずき

- **症状**: 敵が棒立ちで動かない → **原因**: `With` を 1 つも呼んでいない、または全候補の `Score` が 0 以下（`bestScore` の初期値が `0f` なので 0 点は不参加） → **対処**: 立候補させたい候補は必ず正の得点を返す。`Sample_ChaseConsideration` はターゲットが見つからないと 0 を返すので、名簿への `Register`（陣営付き）も確認する
- **症状**: 強い候補を足したのに採用されない → **原因**: 得点が既存候補より低い、または同点で後着になっている → **対処**: 得点の帯を設計する（デモは 追跡 50 / 攻撃 100）。同点なら `With` の順序を前へ
- **症状**: メタAIの指示を発行しても敵の行動が変わらない → **原因**: `AiOrders` は思考への**入力**であり強制ではなく、読まない候補には効かない → **対処**: 候補の `Score` で `context.Orders.AttackPermitted` / `AggressionPermille` / `FocusTarget` を実際に読む（`Sample_AttackConsideration` が手本）
- **症状**: 指示書が 1 フレーム遅れて効く・攻撃権が下りた直後の挙動が不安定 → **原因**: `AiDirector.Tick` をユニットの Tick より**後**に呼んでいる → **対処**: `TickPipeline` の同一フェーズへ `director.Tick` → `characters.Tick` の順で登録する（登録順が実行順）
- **症状**: `[O]` を切ったのにプレイヤーが歩き続ける・ガードが解けない → **原因**: `ReleaseAll()` を呼んでいない（`ManualLogic` に最後の移動・ガードが残る。`Drive` を止めても値は上書きされないため） → **対処**: 自動操縦 OFF の瞬間に必ず `_playerEmulator.ReleaseAll()`
- **症状**: `ArgumentNullException: query` / `roster` → **原因**: `AiBrain` の第 1・第 2 引数が null（`CharacterRegistry` の取得前に組み立てている） → **対処**: `CharacterRegistry` が両インターフェースを兼ねるので同一インスタンスを 2 回渡す
- **症状**: リスポーンした敵がクールダウン明けの状態から始まる／始まらない → **原因**: `AiBlackboard` を使い回している（`TimeSeconds` も記憶も残る） → **対処**: プール再利用・リスポーン時に `Clear()` を呼ぶ（`TimeSeconds` も 0 に戻る）
- **症状**: 敵が同時に殴りかかってきて理不尽 → **原因**: `AttackTokenPool` の返却漏れ（`TryAcquire` は保持済みなら true のままで二重カウントしないが、`Release` は自動では起きない） → **対処**: 攻撃終了・死亡・フェーズ再入のタイミングで `Release` / `Clear` を呼ぶ責務はディレクター側
- **症状**: リプレイ結果が毎回変わる → **原因**: 候補の中で `UnityEngine.Random` などグローバル乱数を読んでいる → **対処**: 決定的乱数をコンストラクタで注入する
- **症状**: `Act` の中の 1 回きりの処理が連射される → **原因**: `Act` は採用され続けるかぎり毎フレーム呼ばれる（`Think` は毎 Tick 走る） → **対処**: 黒板に発動時刻を書いて次フレームの `Score` を 0 に落とす（4 節の必殺技が実例）。なお `BehaviorKey.Attack` の要求自体は、攻撃中の Behavior が `DesiredTransition` で `None` を返すため取りこぼしにも二重発動にもなりません

## 7. 増やす・拡張する

- **思考候補を増やす**: `IAiConsideration` 実装 1 クラスをアプリ側（`Assets/Script/App/Samples/` 等）に新設 → 構築箇所（`Sample_BattlePhase.BuildEnemyUnit` / `BuildPlayerUnit`）へ `.With(new XxxConsideration(...))` を 1 行。**`Score` は世界を変更しない**（読み取りのみ）、書き込みは `Act` で、が規約
- **采配ルールを変える**: `AiDirector` を派生し `Tick(float)` 内で `SetOrders(id, new AiOrders(...))`。取り下げは `ClearOrders(id)`（以後 `AiOrders.Default` ＝全許可に戻る）。手本は `Assets/Script/App/Samples/Sample_BattleDirector.cs`
- **メタAIを外す**: `AiBrain` の第 3 引数を省略するだけ（`NullOrderSource` になり全ユニットが完全自律）。未発行ユニットへの `GetOrders` も `AiOrders.Default` を返すので、一部だけ采配する構成も安全です
- **同時攻撃数を絞る**: ディレクターに `AttackTokenPool` を持たせ、`TryAcquire` の結果を `AiOrders.AttackPermitted` の裏付けにする（4 節の `SquadDirector`）
- **記憶を持たせる**: `AiBlackboard` に `int` キーで読み書き。キーの発番はアプリの定数クラス（`ScreenId` と同じ流儀）。既存の頭脳へ黒板を外から渡すなら `new AiBrain(query, roster, orders, blackboard)` の第 4 引数
- **ターゲット選択を変える**: `Sample_AiTargeting.TryFindTarget` を差し替え・拡張する。既定は「指示書の `FocusTarget` が生存していれば優先、居なければ `Roster.Query(faction, aliveOnly: true, buffer)` の先頭（＝在籍登録順の最初の生存者）」。最も近い敵を選ぶ・ヘイト値で選ぶ等はここに書きます
- **自動操縦の対象を増やす**: 対象ユニットの `ManualLogic` に `InputEmulator` を 1 つ作り、毎フレーム `Drive(brain.Think(in frame))` を呼ぶ。解除時は `ReleaseAll()`。デモプレイ・カットシーン・チュートリアル誘導も同じ経路です
- **ステージごとに難易度を変える**: `Sample_StageSpec.EnemyAttackInterval`（草原 4.0 / 火山 2.5 / 迷宮 3.5 / 市街 3.0 秒）をデータ側で増減する。ディレクターは基準値を受け取るだけで、コード変更は不要です
