# 10. Seed.UI — 画面の登録・遷移・演出

画面（`UIScreen`）の登録・レイヤ別切替・戻り履歴・出入り演出。
`UISystem` が `ShowScreenCommand` / `CloseScreenCommand` の処理者（入口が一本化）。
レイヤは Base（同時1枚・履歴あり）/ Overlay（複数常設）/ Modal（LIFO スタック）。

## デモで確認する

- 戦闘フェーズ入場 → `Sample_HudScreen`（左上に HP 行）が ShowScreenCommand で表示される
- 攻撃・被弾のたび HUD の HP が減る——**出来事は Hub 購読（CharacterDamaged）で更新**する実例
- 決着 → `Sample_ReactionPolicy` が `ShowScreenCommand(Result, Replace)` を発行し
  リザルト画面へ置き換わる（「出来事→画面遷移」の方針クラスの実例）
- Register 直後の画面 GameObject は SetActive(false)（Hierarchy で確認できる）

## 最小コード（新しい画面を1枚作る＝3点だけ）

```csharp
// 1) 画面クラス（ScreenId の値割り当てはアプリの定数クラス）
public sealed class MyScreen : Seed.UI.UIScreen
{
    public override ScreenId Id => new ScreenId(10);
    // 既定 Layer=Base。Overlay/Modal は override で宣言
    protected override void OnShow() { /* Hub.Subscribe はここ。荷物は Payload */ }
    protected override void OnHide() { /* 購読解除はここ */ }
    // 演出が要るなら CreateShowTransition/CreateHideTransition で IScreenTransition を返す
}

// 2) 組み立て（フェーズ or 永続ルート）
var router = new ScreenRouter();
var uiSystem = new UISystem();
uiSystem.Initialize(hub, router, services);
var screen = new GameObject("MyScreen").AddComponent<MyScreen>();
uiSystem.Register(screen);   // 必ず UISystem.Register 経由（Hub/Services が配られる）

// 3) 表示は命令の発行だけ（どの基盤からでも）
hub.PublishCommand(new ShowScreenCommand(screen.Id));  // 既定 Push（Back で戻れる）
// 演出を使うなら毎フレーム: uiSystem.Tick(実時間dt);
```

遷移モード（`ScreenTransition`）: Push（履歴に積む）/ Replace（置換）/ ClearAndShow（履歴全消去。タイトルへ戻る等）。

## ハマりどころ

- **Register は必ず UISystem.Register 経由**（Router 直登録だと Hub/Services が null のまま）
- OnShow/OnHide は演出完了を**待たず即時**（演出は艶。状態変更に関与しない）。
  抜け演出中も GameObject は残り、完了時に Router が非表示化（クロスフェード可）
- Base レイヤは Close で閉じない（Back() か次の Show で遷移）。履歴上限32
- 未登録 ID の Show・ID 二重登録は HubException（フェイルファスト）
- 毎フレーム値（ゲージ等）は Hub でなく Services の問い合わせ IF（ICharacterQuery 等）を読む
- プレハブのロード戦略は基盤に無い——外側でロードしてから Register する
- デモの画面は OnGUI の最小構成。実プロジェクトでは uGUI / UI Toolkit の UIScreen に置き換える
